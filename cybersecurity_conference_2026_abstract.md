# SpecieHop: Trustless Multi-Hop Payments for Decentralized Speculative LLM Inference

Centralized LLM providers impose lock-in, opaque pricing, and single points of failure. In decentralized inference, anyone with a spare GPU can sell it, but the provider is untrusted and the client cannot tell what work it pays for. Yet many clients own a laptop, phone, or edge device that can run a small LLM, which enables speculative decoding. We present SpecieHop, a trustless payment system for decentralized speculative LLM inference. The client drafts tokens on its own device, a provider's large model verifies them, and each verification records the work done, so the client pays per accepted token. Speculative state channels settle each round off-chain, though its amount is known only after verification, and a payment-aware KV cache scheduler evicts clients that stop paying.

A payment channel joins exactly two parties, so reaching a new provider normally costs two ledger transactions and a locked deposit, which can outweigh the inference itself in a short session. Routing payments through intermediaries, as in Lightning-style networks, does not carry over directly. First, the amount is known only after the GPU has verified the draft, whereas hash-locked payments fix it beforehand. Second, a hash preimage proves that payment happened, not that the client received the result. Third, once sessions are free to open, a client can take one result per session and never pay, because in speculative decoding the result is the service.

SpecieHop routes payments over multiple hops, so a client with one funded channel can pay any provider through untrusted relay Hubs. Drafts and results travel directly between the client and the serving Hub, and only locked payments travel along the route, so relays never see prompts. The provider seals each result under a key that is also the payment secret, so payment and delivery are one event. Each hop locks an amount priced by the signed outcome, with a request-price fallback, so every verification is paid for, even by a client that never confirms receipt. Per-relay tweaked point locks stop colluding Hubs from skipping an honest relay and taking its fee. Pipelining sends the next batch's locks while the client drafts, so payment latency is hidden as long as the payment path is faster than drafting. When the provider evicts a session, every lock on the route clears together. The threat model allows any set of clients and Hubs to deviate arbitrarily, and an honest relay never loses funds.

Our single-hop prototype on a real GPU and live blockchain adds under 1 ms of payment cost per round and is 1.39x faster than autoregressive decoding. For multi-hop routing, an analytical model (not yet a measurement) shows that the cost of routing is locked capital, not latency. For honest traffic, routed collateral grows linearly with path length, to about n times a direct session. Under a stalling Hub it grows quadratically, with a constant set by ledger finality: the worst-case lock on the client's first link is seconds on a fast-finality ledger, and about an hour for five hops on an Ethereum-L1-like ledger. We state the limits openly. SpecieHop does not prove that the model computed correctly, since wrong but self-consistent results are deterred economically as in our prior work. It does not hide the route, because relays learn each batch's accepted count, and it bounds stalling but does not prevent it. Next steps are formal security proofs, a simulator for collateral, latency and jamming, and a three-hop prototype on a live blockchain.
